Act as a senior web application QA engineer, API tester, and performance analyst.

The application is already developed and working. Perform a comprehensive quality test of the web application and all connected APIs.

Do not test Android, iOS, Capacitor, native plugins, app-store builds, or mobile installation packages.

## Primary objective

Test and validate:

* All web application screens
* Navigation and routing
* Buttons, links, menus, tabs, and interactive controls
* Forms and validation
* Authentication and session handling
* Role-based access
* API connectivity and responses
* Loading, empty, success, and error states
* Page-load speed
* API response speed
* Browser responsiveness
* Console errors
* Network errors
* Security-sensitive frontend behavior
* Cross-browser compatibility
* Regression stability

Create automated tests where practical and generate a detailed QA report.

## Safety and execution rules

1. Inspect the existing codebase before making changes.
2. Detect the framework, routing system, API client, authentication method, package manager, environment variables, and existing test tools.
3. Use the existing test framework where possible.
4. Do not rewrite the application architecture.
5. Do not change working business logic unless fixing a confirmed defect.
6. Do not use destructive operations against production data.
7. Prefer a staging or test environment.
8. Do not expose API keys, tokens, credentials, or personal data in reports or logs.
9. Do not mark a test as passed unless it was actually executed.
10. Record every source-code, configuration, package, and test-file change.

Use these baseline thresholds unless the project defines stricter targets:

* Authenticated dashboard usable within 4 seconds

* API-backed navigation within 2.5 seconds
* Button feedback within 200 milliseconds
* No unexpected layout shift after load
* No unnecessary duplicate API calls
* No single non-report API call exceeding 3 seconds without explanation
* No page remaining indefinitely in a loading state

Run Lighthouse or equivalent performance testing for the main routes.

Identify:

* Oversized bundles
* Unused JavaScript
* Unoptimized images
* Render-blocking resources
* Excessive rerenders
* Large tables rendered without pagination or virtualization
* Duplicate network requests
* Sequential API calls that could run in parallel
* Missing caching
* Slow backend endpoints
* Excessive API payloads
* Memory leaks
* Long-running browser tasks

Do not make performance changes until the bottleneck is measured.

## Defect reporting

For every defect, document:

* Defect ID
* Title
* Severity
* Priority
* Screen or API
* Route or endpoint
* Browser
* Environment
* Preconditions
* Reproduction steps
* Expected result
* Actual result
* Screenshot
* Console log
* Network request and response
* Suspected root cause
* Recommended fix
* Retest status

Use these severity levels:

* Critical: application unavailable, login failure, data loss, security breach, core workflow blocked
* High: major feature fails with no reasonable workaround
* Medium: partial failure with a workaround
* Low: cosmetic or minor usability issue

Only fix issues automatically when they are:

* Clearly reproducible
* Low risk
* Supported by a failing test
* Compatible with the current architecture

After each fix:

1. Rerun the failing test.
2. Run related regression tests.
3. Run the critical smoke suite.
4. Document files changed.
5. Record before-and-after results.
